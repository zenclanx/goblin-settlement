## 第 0 组：基线复验（必须先绿）

老版曾在专用世界通过；后面二十多轮改了工人路径、存档结构、渲染层。**先确认它们还在。**

- [ ] 两居民、多工地：从**真实箱子**取料 → 走到工地 → 放方块 → 逐块推进。期望：真的搬、真的放，材料真的从箱子里少了。
- [ ] 工人**死亡**：在途工人死亡后，工地/计划不卡死，材料不凭空消失。
- [ ] 工人**取消**：管理员取消后，计划与工人的占用都释放，不出现"永久占用工人"。
- [ ] **区块卸载再回来**：离开聚落（生产暂停）→ 回来后从保存状态继续，**不重复扣料、不重复发料**。
- [ ] 一格小麦：播种 → 生长 → 收获 → **补种归仓**。
- [ ] 上述任一失败：**停下**，那是地基问题，不是新功能问题。

**另记一条验证通道的坑**：客户端 `mods/` 里那个 jar **每次构建后都要刷新**。首次进服被踢（"2 个无法识别的注册表项 / `goblin_settlement`"）就是旧 jar 所致，与代码正确性无关。

## 第 11 组：音效（第七十七轮，全部只能进游戏听）

40 个音档与 `sounds.json` 已入模组，**20 个 `SoundEvent`** 注册、**20 条中英字幕**补齐；受击/死亡/工作号子挂在居民上、五阶移动音挂在傀儡上、傀儡核心走**客户端循环**；居民碰面会一人招呼、另一人应答。编译与 **24 项**独立检查已通过（比上轮多一项 `SoundsCheck`，它钉住 id 不漂移、音档存在、字幕键中英全覆盖无孤儿、以及碰面纯规则），但**这一轮一次游戏都没进过**——下面每一条都只有进游戏、戴上耳机才知道。

- [ ] **⭐注册冒烟（本组最要紧的一条，先做）**：进游戏后**真的放一次自制音**——`/playsound goblin_settlement:entity.goblin.male.greeting master @s`，或直接打一只居民听它受击。**期望：响得出声**。**为什么单列**：24 项检查里**没有任何一条覆盖"注册这件事本身"**——`GoblinSettlement` 里那句 `ModSounds.initialize()` 一旦被删掉，**其余检查全都还是绿的**，而交出去的 jar 会带着 20 个未注册的事件（`/playsound` 报没有该声音、实体一声不响）。这是当初为了能让独立检查加载得动 `ModSounds`、把注册从类初始化器挪进 `initialize()` 之后留下的**唯一缺口**，只有真机播放能补上。**进游戏前先确认客户端 `mods/` 里的 jar 是本次构建的**（第七十六轮记过：旧 jar 会以"无法识别的注册表项"的形式把人踢下线，与代码正确性无关）。
- [ ] **傀儡核心有没有接缝**：五阶核心是 4 秒**可循环**素材，由客户端 `SoundInstance`（`looping = true`）循环。**期望：听不出接缝**——若每 4 秒听到一次"咔"或音量回落，说明循环没接上（选客户端循环这条路正是为了无缝；若仍有缝，则该路线不成立、要回到"素材能否真循环"上）。
- [ ] **被移除/死亡时核心真的停**：打死或 `/kill` 一只傀儡；再测**离开视野/卸载区块**那一路。**期望：声音随实体消失而停**，不留孤儿循环。**重点看卸载那一路**——停止判据是 `!isAlive() || isRemoved()`，"区块卸载"与"实体被移除"是两回事。
- [ ] **【第七十七轮修复波新增】静音之后再开声音，核心还能不能回来**：站在一只傀儡旁边，把**中立（友好生物）音量滑到 0**，停几秒，再推回来。**期望：嗡嗡声回来**。**为什么单列**：`SoundEngine.play` 在算出的音量为 0 且 `canStartSilent()` 为假时**直接返回 `NOT_STARTED`、根本不登记这个实例**，所以"表里有一个实例"并不等于"引擎正在响"——照旧的写法会一直以为它在响，**解除静音后再也不补播，这只傀儡整场静默**，直到区块卸载或它换阶。修法是把"引擎里没有它"当成"没在响"（`SoundManager.isActive`）。**一次性音效没有这个问题**（每次都是新实例，自己会好），所以只有循环这一路要看这一条。**顺带一句**：音量仍为 0 时每客户端 tick 会重试一次——实例表按实体 id 建、不会涨，这是修复的代价，不是缺陷。
- [ ] **【第七十七轮修复波新增】刚出现的居民会不会立刻开口**：让几名居民都在干活，然后**走远到区块卸载、再走回来**（或杀掉再刷出）。**期望：回来的头一个冷却周期（60 秒）内是安静的**，之后才各按各的节拍唱。**为什么单列**：冷却时刻是**瞬态**的、随实体一起消失，而旧写法把初值 0 读成"很久没唱了"——于是任何游戏时间超过 `1200` tick 的世界里，**整批重载的居民会在各自的第一个工作 tick 齐声开口**。修法是把"居民出现后的第一个工作 tick"当作"刚唱过"。**代价是刻意的**：新生成的居民也要等一个冷却才会第一次唱（招呼那边没有这个问题，它的表按 UUID 记、跨区块重载还在）。
- [ ] **招呼是不是太频繁**：让几名居民在同一片走道上来回。**期望：不吵**——每人招呼后进 30 秒冷却（`GreetingRules.GREETING_COOLDOWN_TICKS = 600`）、每 5 秒（`GreetingCoordinator.INTERVAL_TICKS = 100`）最多挑一对、半径 3 格（`GreetingCoordinator.RADIUS = 3.0`）。这三个数**全是发明值**，正是这一条要定的；太频繁或太稀疏都记下来待重定（另见第 9 组）。
- [ ] **招呼与应答的两声顺序**：应答排在 12 tick（`RESPONSE_DELAY_TICKS = 12`，约 0.6 秒）之后。**期望：先一人招呼、隔一小拍另一人应答**，不是同一拍互相抢话。**边界**：应答者在这 12 tick 里死了/走远了，这一声就不响、也不补发（表是会话内存态、不落盘，重载最多少听一声应答）——**这是有意，不是缺陷**。
- [ ] **五阶移动音认不认得出是不同阶**：让木/石/金/钻石/黑曜石各走一段。**期望：五阶脚步声彼此可辨**（每阶 3 个变体由游戏自选，不额外掷骰）。**注意：原版铁傀儡沿用原版步音是对的、不是缺陷**（`GolemTier.hasCustomArt()` 为假时回落 `super.playStepSound`）。
- [ ] **整体会不会太吵**：一群傀儡一直在循环、加上一群居民打招呼时的听感。**期望：不淹没环境音**；若太吵，调的是音量/频率，不是关掉功能（本轮未加音量或混音选项，一律用原版设置）。
- [ ] **男女声音听不听得出区别**（美术原话："样音必须试听确认，**不以频谱代替听感**"）：找一男一女各触发一次招呼/受击。**期望：一听就分得出**。**儿童用的是成年声音、按性别**（美术把儿童专属声音留到后续），所以儿童听起来像大人是**有意**的。
