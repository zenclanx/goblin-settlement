# 统一测试清单（专用测试世界）

整理日期：2026-09-29。**来源**：`UpdateLog.md` 八十个轮段里的 29 条"未完成/不可纯测"，按**执行顺序**重排（不按轮次）。

**为什么要这份清单**：整支分支从建立到现在，**一次游戏都没进过**——所有证据只有编译与 21 项独立检查（纯函数）。下面每一条都是"只有进游戏才知道"的项。散在日志里会漏，且没有顺序。

**顺序为什么重要**：第 0 组是**曾经在游戏里跑通过**的老能力（2026-09-25 的旧版基线）。**先让基线绿**，再往后走；后面每一条失败时才不必怀疑"是不是地基被挖了"。

**怎么做记录**：每组的结论按项目规矩**追加**到 `UpdateLog.md` 末尾（新段，带 `+08:00` 起止与逐条时间）；发现新问题也追加，不改旧条目。测试用世界与常用存档分开，**不要在常用存档上跑**。

## 第 0 组：基线复验（必须先绿）

老版曾在专用世界通过；后面二十多轮改了工人路径、存档结构、渲染层。**先确认它们还在。**

- [ ] 两居民、多工地：从**真实箱子**取料 → 走到工地 → 放方块 → 逐块推进。期望：真的搬、真的放，材料真的从箱子里少了。
- [ ] 工人**死亡**：在途工人死亡后，工地/计划不卡死，材料不凭空消失。
- [ ] 工人**取消**：管理员取消后，计划与工人的占用都释放，不出现"永久占用工人"。
- [ ] **区块卸载再回来**：离开聚落（生产暂停）→ 回来后从保存状态继续，**不重复扣料、不重复发料**。
- [ ] 一格小麦：播种 → 生长 → 收获 → **补种归仓**。
- [ ] 上述任一失败：**停下**，那是地基问题，不是新功能问题。

## 第 1 组：渲染层（第六十一～六十五轮，改动最集中且最不可纯测）

一具身体一具身体地看。**先看成人**，再看儿童、职业、傀儡。

- [ ] **成年男 / 女**：性别是否正确（借用繁殖角色推出）——男女各自一套身体与贴图。
- [ ] **缩放与脚底**：模型**站在地面上**、不悬空、不陷进地里；与 `1.45` 高碰撞箱大致相称。生成器曾犯过"按 y=0 缩放"的错（会让所有模型浮空 0.75 格），交叉校验对它是**结构性失明**的。
- [ ] **耳朵与头发**：各在两侧超出碰撞箱约 **0.23 格**——确认是"轻微穿墙"而不是明显错位。
- [ ] **走路、转头、摆臂**：程序化动画是否自然；模型变大后四肢比例对不对。
- [ ] **15 套职业外观**：七职业 × 男女各自**认得出是哪个职业**；六职业与 `UNASSIGNED` 是否**正确回退基础身体**（不是缺贴图占位）。
- [ ] **女哨卫**：本轮**未接入**（美术贴图差 1–2 行），应看到**基础女体型**——**看到缺贴图是错的**。
- [ ] **儿童**：男孩、女孩**比成人明显矮**（约 66%）；与成人并排比例协调；**长大那一刻会换体**（年龄同步每 10 tick 刷新）。
- [ ] **儿童碰撞箱**：本轮**刻意未改**，仍是成人尺寸。确认"小模型装在大箱子里"没有造成奇怪的手感（例如头顶撞不到该撞的地方）——**这是已知边界，不是缺陷**。
- [ ] **五款傀儡**：木 / 石 / 金 / 钻石 / 黑曜石**各自贴图正确**、不串皮；按阶升级时**当场换皮**（等级此前根本没同步，这轮才补上）。
- [ ] **傀儡核心发光**：胸口核心与眼睛**全亮发光**（自写 `CoreGlowLayer` + `RenderTypes.eyes`）；发光位置**贴在正确的阶的网格上**，不脱位、不串到别阶。
- [ ] **旧档 IRON 傀儡（若有旧档）**：迁移前**短暂不渲染**（约 5 秒）是**刻意选择**（不画胜过崩、胜过穿错皮）；**看到客户端崩溃就是错的**。
- [ ] **多人同屏**：一堆哥布林 + 傀儡同时在场时的帧率；1024×1024 贴图（职业/傀儡）与 512（基础）的显存占用。

## 第 2 组：命令与显示

- [ ] `goblinsettlement status`：每一行都读得通——公共库存、`Housing:`（床位/已占/空位/**无房人数**）、`Homes:`（逐栋**住几人/容量**，卡住的带原因）、`Links:`（路/桥连通，含`缺口`/`受阻`/`n not loaded`）、`Road traffic:`（通行量）。
- [ ] `work`：职业、当前工作阶段、等待理由（含哨卫"目击后报警"写入的理由）。
- [ ] `project`：按材料各一行的短缺报告。
- [ ] `plan`：材料词参数（认识/不认识时的明确失败与可选值列表）。
- [ ] `traffic bridge`：桥种词 `wood` / `stone`。
- [ ] 所有**不可 tick 区块**的房/链接被**跳过并计数**，而不是按未加载的方块判定。

## 第 3 组：住宅

- [ ] **建造**：五级几何按**先容量轴、后品质轴**推进；数据文件里的三套风格（cottage / lean_to / side_porch）**实际会用到**且都能建起来。
- [ ] **材料泛化**：数据文件里声明什么方块，工人就取什么、放什么（不再写死橡木木板）。
- [ ] **提品质不破人口上限**：容量轴满了之后房子还能变漂亮，且**不再多住人**。
- [ ] **床位绑定**：新床落在 8 格内有空位的房子附近；**没有任何房子有空位时**回到自由放床（逃生口）。
- [ ] **住户分配**：居民被分配进有空位的房子；**无房人数**随建造下降；**住满的房子里的母亲生育是否被挡住**（终审改成"聚落里还有空位"的判据——**旧的户级判据会死锁**，这轮修的就是它）。
- [ ] **改建安全诊断**：**玩家在蓝图格里放方块或床**把某栋房卡住时，`status` 那一行**说得出来**是卡在哪一步（本轮只报告、不清理）。
- [ ] **删风格是危险操作**（别在测试中做）：删数据文件里一套风格会让旧档里用它建成的房子**静默变成 cottage**。

## 第 4 组：交通

- [ ] **自主立项**：需求档到 TRANSPORT 时**真的会立项**修路/架桥，且与扩地互斥。
- [ ] **探测**：长草河岸/杂物的分类正确（曾把长草河岸误判为阻挡，导致对岸永远架不成桥）。
- [ ] **无法服务的目标**：不会永久顶住需求档、把扩地冻死（有持久化延期名单）。
- [ ] **施工**：居民真的搬运、铺路、架桥；桥按顺序（引道 → 桥台支撑 → 桥面 → 护栏 → 照明）。
- [ ] **连通验收**：桥**开通前必须可跨越**，路**必须真的接上设施**；不连通时栅栏留着、不开通。
- [ ] **通行量采样与加宽**：走得多了路**真的加宽**（2 → 3 → 5），中线对齐、旧路面被替换掉。
- [ ] **石桥**：13–24 格跨度真的**勘察出来并建起来**；圆石结构；护栏仍是木栅栏（**有意的边界**）。
- [ ] **边界**：>24 格水面不可跨；宽且深的峡谷仍失败（深度上限未动）；非活动区块的恢复。

## 第 10 组：公告牌方块（第七十六轮，全部只能进游戏看）

本模组**第一个方块、第一个物品、第一条网络通道**。编译与 **23 项**独立检查已通过，但**方块外观、四向朝向、两个碰撞形状、面板排版、营地那块挡不挡路一律不可纯测**——下面每一条都只有进了游戏才知道。

- [ ] **放置与朝向**：公告牌能放置；四向 `facing` 与模型正面一致（美术称模型正面朝北）。**期望：方块正面正对放置它的玩家**——代码取的朝向是玩家视线方向的反向（`getHorizontalDirection().getOpposite()`），与熔炉同一套，所以**正面朝向玩家、不是背对玩家**；**看到正面背对着你才是缺陷**。
- [ ] **两个碰撞形状都对**：南北向时板面横跨 x 轴、东西向时横跨 z 轴；**走过去不会被看不见的方块挡住**（板只 3/16 格厚，但碰撞箱非空）。
- [ ] **挖掉方块掉一个公告牌**（`data/goblin_settlement/loot_table/blocks/noticeboard.json` 是否被游戏认到）。
- [ ] **创造模式「功能方块」页里能找到它**，物品图标正常。
- [ ] **右键打开面板**；关掉重开即刷新（本轮无刷新按钮、无 C2S 通道）。
- [ ] **面板六个分区都在**（人口/食物/住房/交通与工程/材料/职业），**长行不溢出**、能**滚动到底**。
- [ ] **中英两套语言下面板文案都正常**：不出现原始翻译键名、不出现字面量 `%s`、没有空缺的占位符。**重点看交通区**：中文界面上不该出现英文整句（`Road traffic: …`），英文界面上不该出现 `受阻`/`缺口`（这两行原先直接传 `status` 的成句，已改成翻译键 + 原始参数）。**库存五项标签应带"已知"**（Known food / 已知食物、Known stock / 已知库存 等）——这些数字只算已加载、可访问的容器，是下界。**住房区那句「蓝图数据不可用」只有把蓝图数据文件弄坏（`HousingBlueprints.available()` 为假）才看得到**，正常世界不必找它。
- [ ] **`goblinsettlement status` 的输出与改动前逐字相同**（这是本轮最有价值的一条；`status` 已改建在共享报告之上、八行由构建期断言钉死，但真机输出仍需人眼核对一遍，**含"无待办交通目标"那一句**）。
- [ ] **营地自动放的那块真的出现**，**且没有挡住居民的走位**（板所在格在生成位与走道之外，但那是静态推断，游戏里要看居民正常走动）。**⚠️ 本项必须用全新世界测**：当前开发世界（`run/`，`goblin-verify`）已有一个已成立的聚落、但没有天然营地，而 `CampGenerationCoordinator` 在这种状态下直接返回——那块板**永远都不会出现**，在这里测只会得到假失败。

- [ ] **没有聚落的维度右键**：面板只显示一行说明，**不崩**。
