# 道路与桥梁的连通验收 设计

更新日期：2026-09-27。依据：GAME_DESIGN.md 第 7 节桥梁施工顺序的末项「两岸引道 → 桥台和支撑 → 桥面 → 护栏 → 照明 → **连通验收**」，以及同节「未完工桥梁禁止通行」；CURRENT_STATUS「交通剩余」第 3 项（自评"正确性问题，体量最小"）。

## 0. 范围

| | 内容 |
| --- | --- |
| **本轮做** | 给已建成的道路与桥梁做**连通验收**：桥在开通前必须真的能过；路必须真的接上目标设施；两者的结论在 `status` 里可见 |
| 不做 | 原版寻路的可达性（坡度、跳跃、门、寻路惩罚一概不判）；自动重铺外部阻挡处；地形适应；成熟期多工程并行 |
| 沿用不改 | 桥既有的巡检预算与"损坏先禁行再维修"路径；路既有的 `firstMissingStructuralStep` 重修路径；两个发明阈值（`TRAFFIC_PER_LANE`、`SAMPLE_INTERVAL_TICKS`） |

**不新增任何持久字段。** 判据是"给定一堆格子和两个端点，问通不通"，结论按需现算。

## 1. 现状（已核对）

- **桥有天然闸门**：`TransportCoordinator.tickPlan` 在 `completedSteps == steps.size()` 时先跑 `firstMissingStructuralStep`，再对 `WOOD_BRIDGE` 调 `clearFinishedBarriers` → `replace(plan.withOpen(true))`。**在此之前桥一直是 `open=false`**，而 `TransportSavedData.index` 会把未开通桥的 `closedFootprint` 并入 `closedFeet`，导航层经 `isBridgeClosedAt(foot)` 把人挡在外面——所以"未完工禁止通行"已经在格子层面成立。**连通验收就该卡在这里**。
- **路没有闸门**：`TransportPlan.isComplete()` 对 `ROAD` 是 `completedSteps == steps.size()`，而设施的"已服务"登记发生在 `replace` 里"由未完成变为完成"那一次。也就是说路一铺完就被当作服务了该设施，中间没有可插入的判定点。
- **路已经有一条修复路径**：`firstMissingStructuralStep` 发现任一非 `BARRIERS` 步的格不是声明的方块，就 `replace(plan.rewind(index))`——被拆掉的格会被重新铺。**连通检查补的是它看不见的那一类：格子都在、但构不成通往设施的通路。**
- **走格与格子的关系**：道路步（`ROAD_GROUND`）与引道步（`APPROACH_GROUND`）的 `site` 是**地面**，人站在 `site.above()`；桥面步（`AIR_OR_WATER`）的 `site` 是**桥面方块本身**，人也站在 `site.above()`。所以这三类步统一：**走格 = `step.site().above()`**。**`BARRIERS` 步不同**——它的 `site` 就是落地走格本身（临时栅栏直接立在走格上），所以**施工期间四个落地格是被自己的栅栏占着的**；§3 因此把"被自己的栅栏占着的落地格"特判为可行走（理由见 §4）。
- **四个落地格存在 `barrierFeet` 里**：`startWoodBridge` 把近岸两个落地、远岸两个落地依次写进去。本设计**只用它的集合（哪四格是落地），不用它的顺序（谁近谁远）**——近远由与锚点的距离决定。
- **加宽计划自身没有 `targetFacility`**（第五十五轮的决定：加宽不是在服务某个设施），而它的走格只是"新增的那一条车道"。所以路这一侧的判据必须**按链**做：目标是**链上根计划登记的设施**，可行走集合是**链上所有成员已放置的走格之并**。
- **`RoadPlanner.accessPositions` 是私有的，本设计不需要它**：目标侧的判定用"离设施四邻（含 y±1）"直接算，不必复用规划器的内部约定。

## 2. 判据（纯层）

新增 `planning/transport/TransportConnectivity`：

```java
/**
 * Whether a walker standing on `from` can reach any of `goals` while stepping only between cells of
 * `walkable`. Four-way steps only: a diagonal gap is not a crossing.
 */
public static boolean connects(Set<BlockPos> walkable, BlockPos from, Set<BlockPos> goals)
```

- 四邻 BFS；访问集保证每格最多入队一次，**代价天然上界 = 集合大小**（实际是计划步数量级，几十到两百格），无需另设上限。
- `from` 不在 `walkable` 里 → 立即为假（人根本站不上去）。
- 空集合、空目标 → 为假。
- **邻接规则**：水平方向只走四邻（x±1 或 z±1），**对角不算连通**；但**允许上下差 1 格**——`y+1` 与 `y-1` 都算一步（居民能上下台阶，路也有坡度）。差 2 格不算。**这条不能省**：桥面比两岸高、路也有上下坡，只走同一层会把每一座桥都判成不通。

## 3. 两个形态

两边的 `walkable` 都只收**计划自己声明的走格**中"没有被外来方块占住"的那些——判定用的是现场，不是意图：

- 一格算可行走，当且仅当它是声明走格，且 `level.getBlockState(cell)` 是空气，**或**该格是 `barrierFeet()` 之一且那里是我们自己的 `OAK_FENCE`（施工标记，不是地形，见 §4）。
- **不需要额外的"脚下结实"判定**：脚下那块是不是声明方块，由既有的 `firstMissingStructuralStep` 负责；本判据只管"人能不能站上去/走过去"。
- 于是两类失败自然分开：**结构性声明格缺失/不符 = `缺口`**（既有 `rewind` 会去修）；**结构都在、但某个走格被外来方块占住 = `受阻`**（只报告，见 §5）。

**桥（按计划）**

- `walkable` = 该桥 `SURFACE` 与 `APPROACHES` 步的走格中上一条判定为可行走的那些。`BARRIERS` 是临时栅栏、不是通路；
- 四个**落地格**取自 `plan.barrierFeet()`（它存的就是四个落地走格），**只用集合不用顺序**；
- `from` = 四个落地格中**离聚落锚点最近**的那个（并列取 x 再 z 最小）；
- `goals` = 四个落地格中**离 `from` 最远**的那些（并列同规则）——也就是对岸那两个；
- 结论 = 人能从这一岸走到对岸。

**路（按链）**

- `walkable` = 链上**所有成员**（原路与各级加宽计划）的 `ROAD_GROUND` 步走格中上一条判定为可行走的那些。**不需要引入计划之外的格子**：`RoadPlanner` 的路线终点本来就是目标设施的相邻格（四邻、含 y±1），所以那一格本来就在计划里；
- `goals` = 上述走格中**与目标设施四邻（含 y±1）**的那些；
- `from` = 上述走格中离锚点最近的一格；
- 目标设施 = **链上根计划的 `targetFacility`**（加宽计划自身留空）；
- 结论 = 人能从聚落这一头走到设施跟前。

## 4. 卡点与行为

**桥：判连通 → 清临时栅栏 → 通过才开通**

该分支的顺序改为：`firstMissingStructuralStep`（缺格 → `rewind` 重修，行为不变）→ **连通判定** → 通过才 `clearFinishedBarriers` 并 `replace(plan.withOpen(true))`。

**为什么判定可以排在清栅栏之前**：四个落地格此刻被**我们自己的**临时栅栏占着，而 §3 的可行走判定把"被自己的栅栏占着的声明走格"当作可行走——栅栏是施工标记，不是地形。这样判定**不必改动世界**就能做，栅栏也就**留在桥上直到真正开通**：一座尚未连通的桥看上去仍在施工，而不是"建好了却被隐形的墙挡着"。`status` 那一侧同理受益——它是只读命令，绝不能为了判定去清栅栏。

**不连通时**：不置 `open=true`、也不清栅栏。桥保持封闭，`closedFootprint` 经 `closedFeet` 继续挡人，所以"未完工桥梁禁止通行"在连通层面同样成立。该分支本来就每 tick 重跑，判定一次 BFS（上界 = 计划步数），代价可忽略。落地格若被**外来的**方块占着，`clearFinishedBarriers` 自己会返回假、桥不开通（既有行为），此时该格在判定里表现为"声明格不可行走"，与 §5 的 `缺口` 口径一致。

**路：检查加报告，不重铺外部阻挡**

在 `completedSteps == steps.size()` 分支里、`firstMissingStructuralStep` 之后加连通判定：

- 不连通**且**存在缺失/不符的声明格 → 沿用既有 `rewind`（既有路径没变，本设计不加新行为）；
- 不连通**但格子都在**（外部阻挡：玩家砌墙、地形改动、设施被围） → **只报告，不改存档、不 rewind**。反复重铺同一段既浪费材料又永远铺不通，这是本设计明确的取舍。

**不新增巡检节拍**：桥的闸门在"要开通"那一刻天然只跑一次；路的结论由 `status` 按需现算，不进 tick 循环。

## 5. 报告

`goblinsettlement status` 在 `Road traffic:` 行之后加一行：

```
Links: all 4 verified
Links: 2 of 4 not connected: 1a2b3c4d road(受阻), 5e6f7a8b bridge(缺口)
```

- **统计范围** = 已建成的**路（按链，一条路一项）** + **所有步已铺完的桥**（`completedSteps == steps.size()`，含尚未开通的——那正是最该被看见的情形）。**判定前先检查该链接的声明走格是否都在可 tick 的区块里**：不在的跳过判定并单独计数（`n not loaded`），不与"已判定连通"混为一谈——`status` 是只读命令，绝不能因为判定而强制加载区块。
- **后缀区分两类**：`缺口` = 该链接有**结构性声明格**缺失/不符（脚下那块不是声明的方块，既有 `rewind` 会去修）；`受阻` = 结构都在，但有**走格被外来方块占住**（只报告不修）。这两类对玩家是"会自己好"与"要你处理"的区别。
- 排序与截断沿用既有风格：按 id 升序，最多 8 条，其余折叠为 `, +N more`。
- 代价：每条链接一次 BFS，链接上限与计划上限同量级（几十条 × 两百格），命令触发时现算，可忽略。

## 6. 验证

- **新增第 17 项独立检查 `transportConnectivityCheck`**（`TransportConnectivityCheck`，纯层）：直通、绕行、被墙隔断、**对角不算连通**、`from` 不在集合、空集合、空目标、目标不可达、同一目标重复、大集合（一次性，验证代价不炸）。
- 完整离线构建 + 全部独立检查（**17 项**）。
- **不可纯测**（会写进日志与状态文件）：桥的开通闸、路的报告、`status` 那一行的可读性，以及在真实世界里"格子在但走不通"到底有多常见。

## 7. 风险与已知边界

- **连通 ≠ 能寻路**：判据只保证"走格在格子层面连得上"——允许上下差 1 格（等同台阶），**不判**跳跃、门、寻路惩罚与原版寻路的其余规则。原版寻路仍可能因为某些地形细节走不过去，本判据**不承诺**居民真能走过去。这是本轮刻意划的线。
- **外部阻挡会长期显示未连通**：按用户选择不重铺。玩家砌了一堵墙挡住引道，就会一直看到 `road(受阻)`。这是有意的：反复重铺比不铺更糟。
- **玩家拆路仍会重修**：那走的是既有 `firstMissingStructuralStep` → `rewind` 路径，本设计不改它，也不受本判据影响。
- **桥的 `from`/`goals` 选边靠锚点距离**：若某天允许"锚点两侧各有一座桥"或跨维度，这条规则需要重看；本轮范围内（单一聚落、单一维度）它是确定的。
- **不判"路通往的不是设施"**：只判"接上了它自己登记的那个设施"。两条路撞在一起、互相借道这类情况不在判据内。
- **加宽计划单独看会不连通**：这正是判据按**链**做的原因；若只按单一计划判，每一级加宽都会被误报为非连通。
- **仍未做游戏内验证**：与本分支既有全部工作一样，本轮只有编译与独立检查的证据。

## 8. 落地结果（实现后补记）

- **设计期的一处事实修正（写进 §2/§3/§5/§7）**：原先只允许"同一层"的四邻步，那会把**每一座桥**都判成不通（桥面高于两岸）——改为**允许上下差 1 格**（等同台阶/坡），差 2 格仍不算。同时"目标格"改为**取自计划自己的声明走格**（`RoadPlanner` 的路线终点本来就是设施的相邻格），不再引入计划之外的格子。
- **纯判据**：`planning/transport/TransportConnectivity.connects(walkable, from, goals)`——水平四邻、允许上下差 1、访问集把代价限在集合大小。第 17 项独立检查 `transportConnectivityCheck` 覆盖直通/绕行/上下台阶/两格高差不算/对角不算/被墙隔断/起点不可站/空集合/目标不可达/两百格规模。
- **存档层**：`TransportSavedData.chain` 公开为 `chainOf`（链的规则仍只在这一个类里），新增 `roadTarget(planId)`——沿链找第一个带 `targetFacility` 的成员，因此加宽计划（自身不带目标）也能答出它服务的是哪个设施。
- **装配（`TransportCoordinator`）**：`bridgeConnects`（走格 = 自己的 `SURFACE`/`APPROACHES` 走格；近岸 = 四个 `barrierFeet` 中离锚点最近者；对岸 = 离它最远的两个）与 `roadConnects`（走格 = **整条链**的 `ROAD_GROUND` 走格；目标 = 与链上根计划的 `targetFacility` 四邻含 y±1 的走格）。**可行走 = 该处是空气，或该格是 `barrierFeet` 之一且那里是我们自己的 `OAK_FENCE`**——自己的施工栅栏不算地形，所以判定是只读的、能排在清栅栏之前。
- **桥的开通闸**：`tickPlan` 的完成分支里，`firstMissingStructuralStep` 之后、`clearFinishedBarriers` 之前插连通判定；不连通就 `return`——不置 `open=true`、**也不清栅栏**，`closedFootprint` 继续经 `closedFeet` 挡人。
- **路只报告**：`status` 新增一行 `Links: …`，按需现算（无巡检节拍、无持久结论）。统计范围 = 已建成的路（按链，一条一项）+ **所有步已铺完的桥**（含尚未开通的）。后缀 `缺口` = 链上有结构性声明格缺失（既有 `rewind` 会去修）；`受阻` = 结构都在但有走格被外来方块占住（不重修）。
- **状态判定的区块闸（任务审查期间加的第二处设计修正，写进 §5）**：判定读的是方块状态，所以 `status` 不能在声明走格落在**不可 tick 区块**时为该链接下结论。每条链接在判定前先过 `level.shouldTickBlocksAt(...)`，不可判定的跳过、单独计为 `n not loaded`——既不加载区块，也绝不把未判定的链接算进"已连通"。
- **明确未做**：外部阻挡不重铺；不判原版寻路的其余规则（跳跃、门、寻路惩罚）；不判"路通往的不是设施"。
