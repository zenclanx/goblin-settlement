## 已实现

- 独立 Fabric 工程与单个发布 JAR：Minecraft 1.21.11、Fabric Loader 0.19.2、Fabric API 0.141.4+1.21.11、Loom 1.14.10、Java 21。
- 每维度一处聚落的 Saved Data：稳定 ID、起始 8×8 地块、玩家保护区、公共箱子、最多八处两格工程及取消记录；旧的单工程字段可迁移。
- 权限入口检查聚落、保护区、认领地块与活动区块；规划和实际放置均复查。区块不活动时暂停，生产代码不强加载。
- 居民保存任务与真实携带物；从公共箱取橡木板、导航和放置，死亡时实际掉落、替补可回收。取消工程保留已建方块，携带物实际掉落；未加载工人的取消记录持久保存。
- 协调器逐个处理多处工地，避免一人占用两处。多个工程共享真实箱子库存，缺料暂停；当前由管理员命令登记箱子与工地。工程查询在公共箱或工人未加载时标示库存不完整，不把未知值误报为精确缺口。

## 已验证

- 固定 Gradle 9.2.1 + Java 21 的离线 build 和人口、地块坐标、保护区、Saved Data 四项检查通过；生成 build/libs/goblin-settlement-0.1.0.jar。单格施工、死亡回收、取消、重载与两人接力的较早验收见 UpdateLog.md。
- goblin-multi-world 中两名居民在不同工地并行施工：共用箱投入 2 块时各完成一格，补 2 块后两处均为 2/2；每次箱内物品与完成方块数一致。缺料的 1/2 工程正常停服重载后可补料接续。
- 两处工程各有工人携带 1 块木板时杀死其中一人：该工程记录地上真实掉落物并释放工人；另一工程继续到 2/2，掉落物被回收利用且无额外木板生成。再补 2 块后原工程也到 2/2。
- 两处工程各有工人携带材料时定向取消一处：被取消工人的 1 块木板掉在地上，工地保持空置，另一处完成第一格。保存重启后取消状态、掉落物和另一处 1/2 进度保留；补 1 块后另一处到 2/2。测试掉落物与强加载已清理，专用服务端已正常停止。
- 两处工人各携 1 块后卸载区块、取消其中一处并停服：重启加载后取消工人变为空闲，地上木板 count 1，原工地为空；另一处工人仍携料并完成第一格。补入 1 块后原取消工人可重新接单完成另一处第二格；箱内为空。测试掉落物与强加载已清理，服务端已停止。
- 多工地死亡掉落在区块卸载与停服重启后仍被追踪：存活工人携带的 1 块和地上掉落的 1 块均保留；重启后回收再施工，两块初始材料对应两个完成方块。补入 2 块后两处工程均为 2/2，四格目标为橡木板、箱子为空。临时强加载已撤销，服务端已停止。
- 工程查询在专用测试世界的区块未加载时显示公共箱库存下界与未知缺口；临时加载后显示精确 0，强加载已撤销，服务端正常停止。最终离线 build 与四项独立检查通过。客户端曾启动到资源图集和渲染线程，但居民模型尚未画面目测。突然断电下实体、箱子和方块的跨存储一致性未验证。
