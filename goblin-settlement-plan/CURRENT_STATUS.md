# 当前状态：哥布林模组接续入口

更新日期：2026-09-25（Asia/Shanghai）。详细历史只追加到 UpdateLog.md。

## 当前任务

阶段 3 的多工地并行施工已完成一轮项目专用服务端验收。下一步把测试用的手动仓库、工地登记发展成聚落自主选址、仓储管理和数据文件蓝图。授权范围仍以用户当轮请求为准。

## 已实现

- 独立 Fabric 工程与单个发布 JAR：Minecraft 1.21.11、Fabric Loader 0.19.2、Fabric API 0.141.4+1.21.11、Loom 1.14.10、Java 21。
- 每维度一处聚落的 Saved Data：稳定 ID、起始 8×8 地块、玩家保护区、公共箱子、最多八处两格工程及取消记录；旧的单工程存档字段可迁移。玩家建筑智能识别、界桩与扩张尚未实现。
- 权限入口统一检查聚落、保护区、已认领地块与活动区块；指派和实际放置均复查。区块不活动时暂停，不在生产代码中强加载。
- 哥布林居民保存任务与真实携带物；从真实箱子取橡木板、导航、放置，死亡后掉落并可由替补回收。取消工程会保留已建方块，携带物实际掉落；卸载工人的取消记录会持久等待处理。
- 工程协调器每秒逐个检查多处工地，避免一个居民同时占用两处工程。多个工程共享真实箱子库存，缺料时暂停；管理员命令用于当前原型的仓库和工程登记。
- 人口、地块坐标、保护区和 Saved Data 编解码检查已接入构建。F001 地块坐标纯计算已由主线实现；函数库其他候选未接入。

## 已验证

- 固定 Gradle 9.2.1 + Java 21 的完整离线 build 及四项检查通过；生成 build/libs/goblin-settlement-0.1.0.jar。此前的单格施工、死亡回收、取消、停服重载和两人顺序接力均已在专用世界验证，细节见 UpdateLog.md。
- goblin-multi-world 中，两处不同工地由两名不同居民分别完成第一格：同一公共箱的 2 块橡木板变为 0，两处第二格仍为空；补入 2 块后两处都达到 2/2，四个目标方块均确认是橡木板，箱子再次为空。
- 同一测试世界中，两个已分别为 1/2 的工程先投入 1 块木板，只有一处完成、另一处保持缺料；保存停服重启后，进度与工人记录保留，补入 1 块后另一处也完成。测试用强加载已撤销，服务端已正常停止。
- 客户端曾启动到资源图集和渲染线程，但居民模型尚未做画面目测。突然断电下实体、箱子和方块跨存储一致性尚未验证。
