# 阶段 4 主线架构：生存与人口

状态：实现中的架构基线。本文沿用 GAME_DESIGN.md 和 TECH_DESIGN.md 的七阶段顺序；尚未实现的内容不视为游戏功能。

## 目标与边界

阶段 4 要形成可持续的“食物与工具 → 居民工作 → 家庭与成长 → 人口额度 → 领地”循环。先接通一个能保存、能恢复的主干，再逐项接入农业、工具、家庭和领地扩张；阶段 3 的客户端开箱与掉落物边界验收后移，不把它们误报为完成。

- `colony` 是居民身份、年龄阶段、家庭关系、孕育名额和人口额度的唯一权威。
- `citizen` 保有实体动作、真实携物和当前工作；实体 UUID 关联名册。实体卸载不等于死亡。
- `economy` 只读取真实箱子和实体库存，提出食物、种子与工具缺口；不保存第二份物品数量。
- `planning` 提出地块或设施候选；`interaction` 核对玩家保护区与领地；`construction` 执行已批准的工地。
- 服务端协调器依据活跃区块中的事实分配工作。避险、食物、基础工具先于扩建；暂停时保留意图，恢复后重新读取真实世界。

## 数据与状态流

1. 居民进入已认领地块时，按稳定 UUID 登记在聚落名册。现有手工生成的哥布林视为成年；以后出生的儿童另由出生流程登记。死亡标记为已故并保留亲属引用，卸载不删名册。
2. 名册只计算活着的成年、儿童和预占孕育名额。人口硬上限 64；只有成年人数进入地块额度 `4 + 2 × 成年人数` 和每 20 分钟的扩张预算。
3. 需求快照每次从真实箱子、居民任务和已登记设施读取。箱子/区块不活动时返回“未知或不可用”，不能把不可读库存当作零库存生成物品。
4. 农田、工具、住房等工作都经过“需求 → 候选地点与材料 → 权限核验 → 持久任务 → 实际物品与方块变化 → 完成登记”。同一居民一次只持有一项主要工作。
5. 孕育先占人口名额，再按有效模拟时间推进；出生提交前重新检查住房、食物和上限。儿童成长同样只按活跃模拟时间推进；重复载入不得重复出生或扩地。

## 分步接入

1. **居民名册**：持久 UUID、年龄阶段、双亲引用；在现有实体生命周期登记/标记死亡；状态命令显示成年、儿童、已占名额及地块额度。此步不声称已经实现自然出生。
2. **需求与工作入口**：建立食物/种子/基础工具/住房的需求快照和稳定优先级，复用现有施工协调器的“已分配居民不可重复领取”边界。
3. **农业与工具闭环**：只在活动且获准的地块收种与耕作，产出进入真实仓库；留种和基础工具材料不得被扩建耗尽。
4. **家庭、孕育、成长**：配对排除近亲，预占名额，按有效模拟时间推进，出生与成熟时更新名册。
5. **领地扩张**：依据成年人口、20 分钟窗口、中心距离、玩家保护区及实际施工能力批准候选地块；人口减少只停止新增，不自动拆除已建设施。

## 当前实施范围

本轮只实现第 1 步主干及最短的编译/存档检查。农活、工具制作、出生和自动扩地仍需后续接入，不把空接口或计划表写成已完成玩法。
